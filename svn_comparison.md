# Git и SVN

1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это указатель на коммит. Создать её можно сразу и без сети: в репозитории появляется короткая ссылка, файлы заново не копируются. В SVN ветка — это копия каталога на центральном сервере. Даже если сервер не дублирует каждый байт, операция идёт по сети и в истории живёт как отдельное дерево. Поэтому ветка в SVN тяжелее.

2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. Коммит в SVN сразу записывается на центральный сервер и получает номер ревизии. Без связи с сервером можно только править файлы у себя. Зафиксировать ревизию нельзя.

3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

SVN остаётся в старых системах, где весь процесс уже построен вокруг одного сервера: так бывает в госсекторе и в банках. Он удобен, когда права на каталоги выдаёт центральный сервер и когда бинарный файл нужно заблокировать, чтобы двое не сохранили его одновременно. Новые проекты начинают на Git.
